# Authentication and Access Model

## Identities

The local environment creates three fictional identities only when passwords are
provided through `.env` or .NET user-secrets:

- `admin@example.test` — `Admin`
- `alice@example.test` — `User`
- `bob@example.test` — `User`

No credential is committed. Passwords are randomly generated by
`scripts/generate-local-secrets.sh`.

## Authentication controls

- ASP.NET Core Identity password hashing
- Unique email addresses
- Account lockout after five failed attempts
- Fixed-window rate limiting on the login endpoint
- HTTP-only, Secure and SameSite cookies
- Thirty-minute non-sliding session lifetime
- Generic authentication failure responses

## Authorisation controls

- The `Admin` controller is protected with a server-side role requirement.
- Ticket queries are filtered by authenticated user identifier.
- Direct ticket requests are checked by `ITicketAccessService`.
- UI visibility is not treated as an authorisation control.
- Negative tests cover cross-user ticket access and administrator boundaries.

## Known limitations

This compressed portfolio implementation uses local ASP.NET Core Identity rather
than a production identity provider. MFA, federation, access reviews and automated
Joiner–Mover–Leaver workflows are documented future extensions rather than claimed
implemented controls.
