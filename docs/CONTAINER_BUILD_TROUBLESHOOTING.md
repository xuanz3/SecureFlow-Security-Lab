# Container Build Troubleshooting Record

## Failure

The first Docker build restored NuGet dependencies successfully but failed during
`dotnet publish --no-restore` with `NETSDK1064`. The message reported that
`Microsoft.CodeAnalysis.Analyzers` could not be found.

## Root cause

The Docker build context included locally generated `bin/` and `obj/` directories.
After the container performed a clean restore, the later `COPY src/SecureFlow.Web/`
instruction copied the host `obj/project.assets.json` over the container-generated
assets. The overwritten dependency graph referenced the host NuGet environment and
was not valid inside the Linux build container.

## Remediation

A root `.dockerignore` now excludes:

- `bin/`
- `obj/`
- test results
- Git metadata
- local `.env` files
- macOS metadata

This preserves the dependency files generated by the container restore and reduces
the Docker build context.

## Validation

The remediation is accepted only when:

1. Release build succeeds.
2. All automated tests pass.
3. Docker image builds from a clean context.
4. Application and PostgreSQL start through Docker Compose.
5. Liveness and readiness endpoints both return HTTP 200.

This record documents an actual failed build and verified corrective action rather
than removing the failure from the project history.
