# Issue and Milestone Map

| Milestone | Primary outcome | Planned backlog |
|---|---|---:|
| M1 — Security Design | Scope, architecture, threat model, requirements and authorised boundaries | 1 completed foundation item |
| M2 — Secure Application | Application, database, identity, authorisation, uploads and logging | 8 items |
| M3 — DevSecOps Pipeline | Build, tests, security scanning, SBOM, DAST and container delivery | 8 items |
| M4 — Security Assessment | Manual testing, vulnerability register, IaC and network evidence | 8 items |
| M5 — Remediation and Detection | Fixes, regression tests, retests, detections and investigation | 5 items |
| M6 — Assurance and Release | Governance, recovery, reports, README and release | 3 items |

## Traceability rule

Every material security finding must link to a GitHub Issue, remediation Pull Request, automated regression where practical, manual retest evidence and final status. Tool output alone is not considered a validated finding.
