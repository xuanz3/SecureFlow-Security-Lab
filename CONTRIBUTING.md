# Contributing Workflow

This is a single-author reference implementation, but changes follow a lightweight professional workflow.

1. Create or select a GitHub Issue.
2. Create a focused branch such as `feat/ticket-authorisation` or `security/fix-upload-validation`.
3. Make small, meaningful commits using conventional prefixes.
4. Add or update tests and documentation with the implementation.
5. Open a pull request with risk, validation and evidence.
6. Merge only after required checks pass.

## Commit prefixes

- `feat:` application capability
- `fix:` functional defect
- `security:` security hardening or finding
- `test:` automated validation
- `ci:` pipeline or scanner
- `docs:` documentation and evidence
- `infra:` Docker or Terraform
- `governance:` risk and control artefact
- `recovery:` backup, restore or rollback
- `chore:` repository maintenance
